# 1.1.0 / build 4：默认隐藏全部桌面文件

日期：2026-11-08。仅本机交付，不推送或发布 GitHub。

## 问题

原版必须先添加隐藏名单，菜单栏眼睛只操作这份名单。用户希望默认单击眼睛就隐藏桌面全部文件，原来的手动指定文件功能继续保留。

## 改了什么

- 单击菜单栏眼睛或主面板主按钮，隐藏点击时桌面全部可见的顶层普通文件和文件夹；再点恢复本次文件与位置。存在未完成会话时优先恢复，不建立第二批隐藏记录。
- 指定文件功能保留在右键菜单、控制面板与名单窗口。全量隐藏不改动原手动名单，名单里的失效旧条目也不阻挡全量操作。
- 界面区分本次隐藏数量与手动名单数量；空名单也能隐藏全部，空桌面直接提示无需隐藏。
- 新恢复记录使用 schema 2，保存操作范围、桌面路径与身份；兼容旧 schema 1 指定名单恢复。记录损坏时保留记录并进入待恢复状态，不能误当成正常显示而退出。
- 继续使用文件隐藏属性与原有位置恢复，不移动文件、不读取正文、不递归改文件夹、不切换 Finder 全局桌面开关。
- 普通文件存在多个硬链接时预先拒绝隐藏，实际写隐藏标记前再次核对，避免连带改变桌面外同一文件。符号链接、特殊文件及重复身份也在修改前拒绝。
- 全量操作过程中出现新可见文件时回滚；完成后新增文件不持续跟踪，下次隐藏时再纳入。原已隐藏文件及点文件保持原状；磁盘等虚拟图标不纳入。
- 增加独立 UI 预览脚本；其文件与恢复记录仅在临时合成桌面，布局为替身，不连接真实 Finder。
- 更新项目说明、决策、使用和隐私说明及交接提示词；版本升为 1.1.0 / build 4。

## 验证

- **本机 arm64 原生隔离测试：54 项通过，0 失败。** 原有 35 项加本版 19 项，覆盖名单独立、全量/指定互斥、重启恢复、旧记录兼容、回滚与中断、文件替换、隐藏期间新增项目、空桌面、损坏/错桌面记录、符号链接/特殊文件/桌面内外硬链接及写入前竞争变化等。
- **真实 AppKit 隔离界面：已实际点击。** 主按钮隐藏全部 3 项；恢复后 3 项显示；指定按钮只隐藏名单 1 项，其余 2 项保持显示；再恢复后无待恢复记录。名单窗口仍只显示原 1 项，按钮与文本无截断。底层隐藏标记通过临时观察记录核对，不只看界面提示。菜单栏左键路径另经代码复查，未把控制面板点击写成菜单栏鼠标实测。
- **双架构构建通过。** 同一个 App 包含 arm64 与 x86_64，最低编译目标 macOS 13；Intel compatibility packs 警告仍存在，但编译、架构核对及签名检查通过。
- **发行包核对通过。** ZIP 实际解压后核对版本 1.1.0 / build 4、两种架构及严格签名；SHA-256 与校验文件一致。
- **通用隐私检查通过。** 检查源码、App 与 ZIP 的个人路径、运行时记录及 Bundle ID；未提供针对个人词汇的额外审计词表。
- Git 差异空白检查通过；分发包清理只作用于本项目 dist 中符合命名规则的文件，保留 1.1.0 与 1.0.2，清除更早的 1.0.1 分发包。历史工作目录、报告、Git 历史和用户数据未清理。
